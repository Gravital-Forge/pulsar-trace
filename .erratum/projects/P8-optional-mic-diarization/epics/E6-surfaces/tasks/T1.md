- [ ] **Step 4: First-enable backfill trigger**

In the composition root (found per Files note), where the toggle's owner can observe changes
(SwiftUI `onChange(of: settings.diarizeMicEnabled)` at the Settings view, or a `didSet` relay —
prefer the composition root over the view so CLI-less app launches still work):

```swift
// PT-P8-R3 (d): first enable backfills the owner profile from existing
// recordings so live "You" works immediately.
func diarizeMicToggled(_ enabled: Bool) {
    guard enabled else { return }
    Task.detached(priority: .utility) {
        let store = OwnerVoiceProfileStore(
            fileURL: AppPaths.standard.ownerProfileURL)
        guard await store.snapshot() == nil else { return }
        let diarizer = Diarizer(configuration: .init())
        let summary = try? await OwnerProfileBackfill.run(
            outputRoots: [/* the app's output folder root — same value the
                             recordings pane scans; reuse its accessor */],
            store: store,
            diarize: { try await diarizer.diarizeStream(wavPath: $0) },
            events: /* the app's EventWriter */,
            logger: Logger(label: LogSubsystem.engine))
        // summary logged; no UI beyond the log line.
    }
}
```

The two `/* … */` holes are wiring, not design: both values exist in the composition root (the
recordings pane already scans the output root; the app already owns an `EventWriter`) — pass the
same instances. If a refine job is running, the backfill's diarizer competes for the ANE — accept
for now and note in the completion record (the queue's PauseGate does not govern ad-hoc work;
promoting backfill to a queue job is a close-out follow-up if it bites).
