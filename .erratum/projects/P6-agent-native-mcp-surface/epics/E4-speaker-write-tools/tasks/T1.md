# PT-P6-E4-T1 · `RecordingGate` — refuse speaker edits during capture

**Epic:** PT-P6-E4

The speaker library is read-only while a recording is in progress (PT-R32). Every speaker write tool
consults a `RecordingGate` first; when a recording is live it returns a recording-in-progress error
and performs no mutation. The gate reads the live recording id through the `RecordingsProviding` seam
(backed in the app by `RecordingViewModel.status`).

## Acceptance criteria

- `RecordingGate(recordings:)` exposes `blockIfRecording() async -> CallTool.Result?` returning an
  `isError` result (naming the live recording) when a recording is in progress, else `nil`.

```swift
import Foundation
import MCP

/// Refuse speaker-library mutations while a recording is in progress — the
/// library is read-only during capture (PT-R32, PT-P6-R5).
// PT-P6-R5
public struct RecordingGate: Sendable {
    public let recordings: any RecordingsProviding

    public init(recordings: any RecordingsProviding) {
        self.recordings = recordings
    }

    /// `nil` when a mutation is allowed; an `isError` result when a recording is
    /// in progress.
    public func blockIfRecording() async -> CallTool.Result? {
        guard let id = await recordings.liveRecordingID() else { return nil }
        return CallTool.Result(
            content: [.text("A recording is in progress (\(id)); the speaker library is "
                + "read-only during capture. Stop the recording before editing speakers.")],
            isError: true)
    }
}
```
