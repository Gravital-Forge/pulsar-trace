# PT-P6-E2-T1 · MCP SDK dependency + `PulsarTraceMCP` library + `MCPTests`

**Epic:** PT-P6-E2

Stand up the new module and test target and wire the official MCP Swift SDK. Nothing functional yet
— this task only makes the package resolve, build, and test green with the new target in place.

> SDK facts (verified against tag `0.12.1`): the package is
> `github.com/modelcontextprotocol/swift-sdk`, the library product is **`MCP`**, platform floor is
> macOS 13 (we are macOS 14), and it builds under Swift 6. It is pre-1.0, so pin it **exact**, the
> same way `FluidAudio` / `argmax-oss-swift` are pinned in this `Package.swift`.

## Acceptance criteria

- `Package.swift` declares the SDK dependency pinned `exact: "0.12.1"`, a `PulsarTraceMCP` library
  target depending on `.product(name: "MCP", package: "swift-sdk")` and `PulsarTraceEngine`, an
  `MCPTests` test target depending on `PulsarTraceMCP`, and `pulsartrace-mac` now depends on
  `PulsarTraceMCP`.
- `swift build` resolves and compiles; `swift test --filter MCPPackage` passes.

## Files

- Modify: `Package.swift`
- Create: `Sources/PulsarTraceMCP/MCPServerInfo.swift`

- [ ] **Step 1: Add the dependency and targets to `Package.swift`**

In the `dependencies:` array, after the `argmax-oss-swift` line:

```swift
        // Official MCP Swift SDK (PT-P6-D2). Pinned exact: pre-1.0, minor
        // bumps carry breaking changes (the HTTP-server transports are recent).
        .package(url: "https://github.com/modelcontextprotocol/swift-sdk.git", exact: "0.12.1"),
```

In the `targets:` array, add the library target (after `PulsarTraceMenuBar`):

```swift
        // The MCP server core (PT-P6-D1): tool registry + JSON-RPC handlers
        // behind a hand-rolled loopback HTTP front end feeding the SDK's
        // StatelessHTTPServerTransport. No SwiftUI — the menubar executable
        // owns the lifecycle.
        .target(
            name: "PulsarTraceMCP",
            dependencies: [
                .product(name: "MCP", package: "swift-sdk"),
                "PulsarTraceEngine",
            ]
        ),
```

Add `PulsarTraceMCP` to `pulsartrace-mac`'s dependencies:

```swift
        .executableTarget(
            name: "pulsartrace-mac",
            dependencies: ["PulsarTraceMenuBar", "PulsarTraceEngine", "PulsarTraceMCP"]
        ),
```

Add the test target (after `MenuBarTests`):

```swift
        // MCP server tests — auth, the loopback listener, and the SDK
        // round-trip, against temp folders and ephemeral loopback ports.
        .testTarget(
            name: "MCPTests",
            dependencies: ["PulsarTraceMCP"]
        ),
```

Also add `PulsarTraceMCP` to the `products` library list if you want it consumable, optional:
not required for the executable. Leave products as-is.

- [ ] **Step 2: Create a minimal module file**

Create `Sources/PulsarTraceMCP/MCPServerInfo.swift`:

```swift
import Foundation

/// Identity the MCP server reports during the `initialize` handshake.
public enum MCPServerInfo {
    public static let serverName = "PulsarTrace"
    public static let serverVersion = "1.0.0"
    /// The default loopback port (PT-P6-D3).
    public static let defaultPort: UInt16 = 8276
}
```

- [ ] **Step 3: Write the package test**

Create `Tests/MCPTests/MCPPackageTests.swift`:

```swift
import Testing
import MCP                       // proves the SDK product resolves
@testable import PulsarTraceMCP

@Suite("MCPPackage")
struct MCPPackageTests {
    @Test("the module builds and exposes its server identity")
    func moduleResolves() {
        #expect(MCPServerInfo.serverName == "PulsarTrace")
        #expect(MCPServerInfo.defaultPort == 8276)
        // The SDK Server type is reachable from this target.
        _ = Server.self
    }
}
```

- [ ] **Step 4: Resolve and build**

Run: `swift build` (bare, `dangerouslyDisableSandbox: true` — this fetches the SDK over the network)
Expected: resolves `swift-sdk 0.12.1` and its transitive deps (swift-system, swift-log), compiles.

Run: `swift test --filter MCPPackage`
Expected: PASS — `moduleResolves`.
