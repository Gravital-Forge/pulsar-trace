# PT-P7-E4-T3 · Non-gating probe job + README badge

**Epic:** PT-P7-E4

The fact-gatherer behind PT-P7-D4: what the hosted VM actually supports — audio devices, BlackHole
viability, SIP posture, CoreML compute devices. Its output is read by humans deciding whether an
audio tier can ever move to CI; it can never fail the workflow.

## Acceptance criteria

- A `probe` job with `continue-on-error: true` logs: `system_profiler SPAudioDataType` before and
  after a BlackHole install + `coreaudiod` restart, `csrutil status`, and Swift-printed
  `MLComputeDevice.allComputeDevices`.
- The job's conclusion cannot gate: even with every step failing, the workflow's required checks are
  unaffected.
- README carries the `ci` workflow badge.

## Files

- Modify: `.github/workflows/ci.yml`

- Modify: `README.md`

- [ ] **Step 1: Add the job**

Append to `jobs:` in `.github/workflows/ci.yml`:

```yaml
  # Fact-gathering only (PT-P7-D4): what does this VM actually support?
  # Never gates — promotion of any audio tier to CI is a project decision
  # made on this job's recorded output, not folklore.
  probe:
    runs-on: macos-15
    timeout-minutes: 20
    continue-on-error: true
    steps:
      - uses: actions/checkout@v7
      - name: Audio devices (stock image)
        run: system_profiler SPAudioDataType || true
      - name: SIP status
        run: csrutil status || true
      - name: Install BlackHole and restart coreaudiod
        run: |
          brew install --cask blackhole-2ch || exit 0
          sudo killall coreaudiod || true
          sleep 5
      - name: Audio devices (after BlackHole)
        run: system_profiler SPAudioDataType || true
      - name: CoreML compute devices (ANE present?)
        run: |
          cat > /tmp/probe.swift <<'SWIFT'
          import CoreML
          print(MLComputeDevice.allComputeDevices)
          SWIFT
          swift /tmp/probe.swift || true
```
